# chirpy-hugo v1.1.0

The second release. Parity is unchanged — the theme still renders the same HTML
and the same pixels as `jekyll-theme-chirpy` v7.6.0 — and the release is about
the things parity alone does not prove: that a configuration option actually
works, that a broken site says why, and that the test suite catches both.

Measured at this tag: **47/47 pages DOM-identical**, **84/84 pixel pairs
identical**, 63 UI checks across four viewports, every gate green.

## 1. What is new

### A build warning when the site is under-configured

`markup` and `outputs` are the two categories Hugo does not merge from a theme.
A site that omitted them built without an error and lost its highlighting
classes, its code-fence attributes, its feed, its search index and its PWA
manifest.

The theme now checks them on every build (`_partials/check-config.html`, run
once through `partialCached`) and prints the exact TOML block to add. The check
is behavioural, because Hugo does not expose `markup` to templates: it renders
a probe block and asks whether the attribute list survived, whether the
highlighter emitted classes and whether the home page published the four output
formats.

### Four analytics providers

`head.html` dispatched to `analytics/<provider>.html`. Four of the six partials
did not exist, so setting `analytics.umami.id` (or Matomo, Cloudflare or Fathom)
**failed the build** with `partial not found`. All six providers are ported
from upstream, and the adoption gate now builds one site per provider family
and asserts the rendered marker.

### Test coverage for configuration, not just markup

- **UI matrix (Gate 5b):** four viewports — desktop 1280, tablet 768, mobile
  390 and small 320 — over the pages that carry every component. No horizontal
  overflow, no script errors, no failed local requests, a viewport meta that
  parses; sidebar open/close through the mask, search open/type/results/cancel,
  TOC popup on mobile; theme toggle and persistence, copy and back-to-top on
  desktop. 63 checks in ~16 s, and the same matrix against the deployment shape
  (subdirectory + minify).
- **Provider matrix:** six analytics providers and three comment providers.
- **Manifest invariants:** every `manual` port must have an existing target;
  every partial a template names must exist, including the two
  configuration-dispatched families; every shipped configuration must declare
  the mandatory settings.

## 2. Performance

- Vendor assets are self-hosted by default (fonts, icons, tocbot, search,
  dayjs, glightbox, clipboard, polyfill), non-critical CSS loads asynchronously,
  and the LCP image plus the body font are preloaded (D-22).
- Mobile home: 66 → 92–97 performance, LCP 6.3 s → 2.1–3.0 s, against 74 / 4.5 s
  for the Jekyll build of the same page.
- The visual matrix captures viewports concurrently (six workers): the full
  84-pair run went from ~66 s to ~33 s. `npm run test:fast` chains the everyday
  checks in ~19 s.

## 3. Fixes

- Enabling Umami, Matomo, Cloudflare or Fathom crashed the build.
- `user-scalable=no initial-scale=1` lost its separator when minified, so the
  browser dropped `initial-scale` and phones rescaled the page when the
  off-canvas sidebar opened. Directives are comma-separated (D-24) and
  `user-scalable=no` is gone: blocking pinch-zoom is an accessibility failure
  and changes nothing visually.
- `app.min.js` treats any non-empty `register` value as true, so
  `register=false` registered a worker that could reload a cached page in a
  loop. The parameter is now emitted only when the cache is enabled (D-25).
- Service worker updates: a new worker skips waiting and claims the page,
  navigation is network-first, and the visitor is reloaded only when a cache
  from an older build existed (D-23).
- Subdirectory deployments: doubled base paths, a missing breadcrumb base
  segment and empty category/tag term lists, all caught by the deployment gate.

## 4. Documentation

- `COMPATIBILITY.md` uses one status vocabulary (`declared`, `closed`, `open`,
  `retired`) and every divergence states its verification.
- `PLAN.md` is complete: the three stale items are resolved (the configuration
  warning is implemented; the two "multilingual" partials do not exist
  upstream; PR CI measures ~55 s against a 12-minute budget).
- `FEATURES.md` counts and the vendor-bundle rows now match what ships.
- `TESTING.md` describes Gates 8 and 9 as implemented, including the new
  invariants and the provider matrix.
- `AUDIT.md` records the second-pass completeness audit, its method and its
  findings.

## 5. Upgrading

No configuration changes are required. A site that already declares `markup`
and `outputs` sees no new warning. A site that does not will now be told
exactly what to add — copy the block from the warning or from
[`docs/CONFIG.md`](../CONFIG.md) §11.

# chirpy-hugo v1.5.2

The code-heavy post on a throttled phone went from **6.4 s to 3.3–3.6 s LCP**
and from **68 to 90–91 performance**. The Jekyll original of the same page
measures 6.7 s and 67.

## What was happening

Lighthouse reported 93 % of the LCP as *render delay* on the post description.
The page preloaded only the body face (Source Sans Pro 400). The other faces
used above the fold — SemiBold 600 for the metadata, Black 900 for the title,
Lato 400 for the headings — were discovered only after the stylesheet, fetched
late at low priority, and swapped in at the end:

```
font discovery: CSS → 3 faces → swap → largest paint moves to 6.4 s
```

## The fix

Preload the four faces that paint above the fold, before the blocking
stylesheets:

```html
<link rel="preload" as="font" type="font/woff2" crossorigin href="…SourceSansPro-Regular.woff2" fetchpriority="high">
<link rel="preload" as="font" type="font/woff2" crossorigin href="…SourceSansPro-SemiBold.woff2">
<link rel="preload" as="font" type="font/woff2" crossorigin href="…SourceSansPro-Black.woff2">
<link rel="preload" as="font" type="font/woff2" crossorigin href="…Lato-Regular.woff2">
```

First paint now uses the final faces: FCP 0.9 s, LCP 3.3–3.6 s, CLS 0.004.

Measured with `npm run test:perf` (Lighthouse mobile, same content, both
builds):

| Page | Port | Jekyll |
|---|---|---|
| Home | 93 performance, LCP 3.0 s | 70, 5.4 s |
| Code-heavy post | **90**, **3.6 s** | 67, 6.7 s |

The preload links are invisible to Gate 4 (they are part of the declared D-22
head divergence), so `test:build` now asserts that the four faces are present
on a post. Without them the regression is a doubling of LCP that no DOM gate
would notice.

## Not changed

- No HTML or pixel difference: parity stays at 50/50 pages and 84/84 pairs.
- The theme bootstrap stays synchronous: the giscus bundle reads the global
  `Theme` while parsing, so deferring it breaks comment-enabled pages.
- Bold 700 is not preloaded; it is used below the fold and would add 77 KB to
  the critical path.

## Compatibility

No configuration changes. Sites with `assets.self_host.enabled = true` (the
default) get the preloads; CDN mode keeps its own font loading.

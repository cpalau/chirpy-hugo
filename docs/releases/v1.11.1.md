# Chirpy Hugo v1.11.1

A parity fix for sites where a tag and a category share a name.

Tracks upstream `cotes2020/jekyll-theme-chirpy` **v7.6.0**.
Parity: Gate G4 ✅ (50/50 pages) · Gate G5 ✅ (18/18 pairs).

## Highlights

- A category keeps its own spelling even when a tag has the same name.

## Added

None.

## Changed

- `layouts/_partials/taxonomy-labels.html` takes a context dict,
  `(dict "page" . "taxonomy" "tags")` or `"categories"`, and returns the
  labels of that taxonomy only. Sites that override a template and call this
  partial with a page must pass the dict.

## Fixed

- **Category label taken from a tag.** Symptom: with a tag `seo` and a
  category `SEO`, the category page, its title and the categories list showed
  "seo". Cause: one label map for both taxonomies, keyed by the lowercased
  name, so the first spelling seen won. Jekyll keeps `site.tags` and
  `site.categories` apart. Fix: one map per taxonomy.

## Breaking changes

Only for sites that override a template and call `taxonomy-labels.html`
directly: pass `(dict "page" . "taxonomy" "tags|categories")` instead of the
page.

## Upstream sync

Still tracking Chirpy **v7.6.0**. Nothing was ported and no `D-xx` changed.

## Parity status

Measured on this commit with Hugo 0.169.0 extended against the Jekyll oracle:

- **G4 (HTML):** 50 pages, 50 identical, 0 with differences.
- **G5 (pixels):** 18 pairs, 18 pixel-identical outside the declared boxes.
- **Full suite (`npm run test:all`):** all gates green, including Gate 4c
  (70 checks, with a tag and a category that share a name).

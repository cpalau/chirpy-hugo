# chirpy-hugo v1.5.3

Found by creating a blog from scratch with the starter and running the gates
over it. Two defects, both fixed, plus the verification.

## 1. The starter had no social card

`ogp.me` requires `og:image`, and a fresh site has no page images. The starter
did not set `social_preview_image`, so every page of a new blog failed the Open
Graph requirement (13 pages, 13 failures in the SEO standards gate).

The starter now ships a neutral `static/img/social-preview.png` and wires it:

```toml
[params]
  social_preview_image = "/img/social-preview.png"
```

## 2. A site without an avatar emitted an empty link

The sidebar always rendered

```html
<a href="/" id="avatar" class="rounded-circle"></a>
```

even when no avatar was configured. With no content and no accessible name that
is an empty link (`wcag/h30`). The anchor is now rendered only when there is an
avatar; sites that set one are unchanged.

## 3. Verified with a real site

`/tmp/opencode/test-blog`, created from `starter/` (not committed, not on
GitHub):

- production build with `--panicOnWarning --gc --minify`: exit 0, 20 pages;
- a second build without minification for validation: exit 0;
- **138 SEO standard checks, 0 failures**;
- every internal link and fragment resolves;
- adoption gate: the fresh site now carries the preview image, no empty avatar
  link, and still builds warning-free;
- parity corpus unchanged: 50/50 pages, 84/84 pixel pairs.

The remaining `html-validate` findings on a fresh site are the inherited upstream
debt already declared in D-20 (lowercase doctype, icon-only buttons without
names, duplicate landmark labels); they appear on the Jekyll build too and Gate 2
only fails when the port is worse.

## Compatibility

No configuration changes for existing sites. A site that wants the starter's
card copies the asset, or points `social_preview_image` at its own image.

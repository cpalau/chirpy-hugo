# chirpy-hugo v1.3.0

The original theme is a faithful Jekyll theme from before several things that
search engines now expect. This release adds them — **off by default**, so the
rendered HTML stays byte-identical to upstream unless a site opts in.

Measured: 50/50 pages DOM-identical, 84/84 pixel pairs identical, 3941 SEO
checks, 197 demo standards, 35 extension checks, zero warnings.

## 1. Automatic when the site uses the feature

These render no HTML on a monolingual LTR site, so the parity gates stay green:

- **`hreflang` alternates and `x-default`.** Every translated page names its
  siblings and points `x-default` at the default language.
- **`dir="rtl"`.** Taken from the language direction, so Arabic, Persian,
  Hebrew or Urdu are laid out and indexed correctly.

## 2. Opt-in

| Key | Default | Effect |
|---|---|---|
| `params.seo.noindex_hidden` | `false` | `noindex` for posts with `hidden: true`; upstream removes them from listings but search engines still index them |
| `noindex: true` (front matter) | honoured | a single page opts out |
| `params.seo.feed_discovery` | `false` | `<link rel="alternate" type="application/atom+xml">` |
| `params.seo.breadcrumbs` | `false` | `BreadcrumbList` JSON-LD from the page hierarchy |
| `params.seo.description_max_chars` | `0` | hard cap for the meta description (0 keeps the gem's 100-word excerpt) |
| `params.seo.image_fallback` | `false` | the social preview becomes the JSON-LD image when a page has none |
| `params.seo.article_meta` | `false` | `article:section`, `article:tag`, `article:author` |
| `params.seo.image_metadata` | `false` | `og:image:type`, plus width/height read from the asset when Hugo can resolve it |
| `params.seo.sitemap_limit` | `50000` | warn when the sitemap passes the protocol limit |

## 3. Tested against the standards

Gate 4c (`npm run test:seo:ext`) builds `tests/fixtures/seo-ext`: English,
Spanish and Arabic (RTL), every switch on, a sitemap limit of 3. It asserts:

- the three `hreflang` values plus `x-default` on every translation;
- `dir="rtl"` only on the Arabic pages;
- `noindex` on the hidden post and on the `noindex` page, none on a normal post;
- feed autodiscovery;
- the description cap ending on a word boundary with `…`;
- `article:section`, `article:tag`, `article:author`;
- `og:image:type` and the dimensions read from the asset;
- the JSON-LD image fallback;
- a two-level breadcrumb on a post and three levels on a term;
- the sitemap warning, no other warning;
- the standards gate over the whole build (Open Graph, Twitter, JSON-LD and
  `BreadcrumbList`).

## 4. Why the additions are opt-in

The project's contract is byte parity with Jekyll. A tag that upstream does not
emit would break that contract for every page, so each addition is a switch:
turning it on is a deliberate decision, and the default site is still the
original. The two automatic ones are exceptions only because they produce no
output unless the site declares translations or a direction.

# chirpy-hugo v1.5.0

Two things this release: the Jekyll plugins are now validated one by one, and
the footer finally credits **this** theme's release instead of the Jekyll one.

## 1. The footer was showing the wrong version

The footer tooltip used `params.theme_version`, which is the upstream Chirpy
version this port reproduces (7.6.0) — correct as a reference, wrong as the
theme's own version. It now reads `data/theme.yaml`, which the release script
keeps in sync with `package.json`, and links to the matching GitHub release:

```html
<a … title="v1.5.0"
   href="https://github.com/cpalau/chirpy-hugo/releases/tag/v1.5.0">Chirpy Hugo</a>
```

`scripts/release.mjs --prepare` bumps both files, `--check` fails when they
disagree, and the deployment gate asserts the built footer shows the release.

## 2. Gate 10: Jekyll plugins, module by module

`npm run test:plugins` validates each plugin against the two builds and reports
the result per module. A module passes only when every check passes; an
exclusion is a documented toolchain property, not a skipped failure.

| Module | Result |
|---|---|
| Pagination | 100 % — page count, pinned-first, both `hidden` spellings, no empty page |
| Archives | 100 % — term URL sets, tag counts, accented slugs |
| Sitemap | 100 % — URL set and every `lastmod` (except D-14 URL shape) |
| Include cache | 100 % — `partialCached`, favicons on every page |
| Last modified | git dates, except single-commit files (D-27) |
| Filters | 100 % — slugify, uri_escape, url_encode, xml_escape, dates |
| MathJax | 100 % as data (formatting differs: Jekyll minifies, we keep the source) |

The battery found and fixed three real differences:

- **lastmod was inconsistent**: the SEO dates and the page label read only the
  front matter, while the sitemap, feed and sidebar read `.Lastmod` (git when
  `enableGitInfo` is on). One post could show two "modified" dates. All five now
  read `.Lastmod`.
- **`uri_escape` encoded too much**: share links for titles with `&`, `+`, `%`
  or `#` differed from Jekyll. It now reproduces Addressable's
  `normalize_component`.
- **`xml_escape` had no equivalent**: `htmlEscape` writes `&#34;`/`&#39;` where
  Ruby writes `&quot;`/`&apos;`. A partial matches Ruby, and the feed uses it
  where upstream does.

## 3. Documented exclusions

- **D-14** — Jekyll's `/page2/` cannot be expressed in Hugo 0.168 (measured:
  `pagination.path` does not substitute a page token). Both gates normalise it.
- **D-27** — `posts-lastmod-hook.rb` only records a date when a file has more
  than one commit; Hugo's GitInfo always exposes the last commit. A site can set
  `lastmod` explicitly or keep `enableGitInfo = false` (the default).
- **MathJax formatting** — semantic equality, not byte equality: Jekyll runs the
  file through its compress layout.

`docs/PLUGINS.md` is the full matrix; `docs/RELEASING.md` documents the version
files.

## 4. Measured

demo standards, 44 extension checks, **47 plugin checks**, zero warnings.

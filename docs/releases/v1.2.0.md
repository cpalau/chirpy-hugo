# chirpy-hugo v1.2.0

SEO parity, end to end. Chirpy does not implement SEO itself: it delegates to
`jekyll-seo-tag` 2.9.1 and rewrites the image tags. The port now reproduces
**every branch of that gem**, proves it against a real Jekyll build, and keeps
the pixels where they were: **50/50 pages DOM-identical, 84/84 pixel pairs
identical**.

## 1. What was missing

The corpus only used the map form of `image` and posts with an explicit
`description`, so several branches had never run. Comparing the live demo with
`chirpy.cotes.page` showed it: a post without `description` published Hugo's
`.Summary` (longer, and it could run into the second paragraph) instead of
Jekyll's 100-word excerpt.

The gem's source was then read line by line (`template.html`, `drop.rb`,
`author_drop.rb`, `image_drop.rb`, `json_ld_drop.rb`) and every branch was
either reproduced or declared.

## 2. What is new

- **Description from the excerpt**: the first block of the post, rendered and
  stripped like `strip_html`, cut to 100 words with `…` — and front-matter
  descriptions are cut the same way. `seo_description_max_words` is honoured.
- **Page-level SEO**: `canonical_url`, `title_category`, `locale` (with `-` →
  `_`), `twitter.card`, and the `seo` map (`type`, `name`, `links`,
  `date_modified`).
- **Images**: `path`/`facebook`/`twitter` fallbacks, `width`, `height`, `alt`,
  `lqip`; dimensions reach both Open Graph and the JSON-LD image object.
- **Authors**: maps, `authors[0]`, the site-wide `author` fallback, `type`
  (`Person`/`Organization`), `url`, and the twitter-name fallback. `@` is
  normalised once, so `@handle` no longer becomes `@@handle`.
- **Site-level**: `logo` produces the JSON-LD `publisher`, `facebook.admins/
  publisher/app_id` produce their tags, and the legacy
  `google_site_verification` works when `webmaster_verifications` is empty.
- **Migration**: `last_modified_at` is accepted next to `lastmod`, and
  `seo.date_modified` wins over both.
- **JSON-LD**: `WebSite`/`WebPage`/`BlogPosting`/`CreativeWork`, `sameAs`,
  `mainEntityOfPage`, `publisher`, and the page-number rule (a paginated home
  page is a `WebPage`, not the site).

## 3. New tests

| Gate | What it does |
|---|---|
| `npm run test:seo` (4b) | field-by-field comparison with the oracle, plus invariants; 51 pages, ~2.4 k assertions |
| fixture 13 | `seo-knobs`, `seo-excerpt`, `seo-images`, mirrored in both sites |
| `npm run test:features` | site-level SEO settings that would change every corpus page |

The SEO gate checks what equality cannot: a canonical or an `og:title` that both
sides omit is still a bug. It also decodes HTML entities, parses JSON-LD (key
order is not meaningful) and normalises the declared divergences (`generator`,
viewport, `/pageN/` vs `/page/N/`).

## 4. Also fixed

- **Home pagination** now excludes `hidden` posts, exactly like
  `jekyll-paginate`. The old code paginated everything and hid posts while
  rendering, so the page count was right only while the numbers happened to
  round the same way.
- The demo ships `social_preview_image` and the upstream author identities, so
  its Open Graph, twitter card and JSON-LD author match the original.

## 5. Declared divergences

- **D-06**: `generator` says Hugo, not Jekyll.
- **D-14**: paginated URLs are `/page/N/` instead of `/pageN/`.
- **D-24**: the viewport meta is comma-separated and allows zoom.
- **D-26**: `image: { twitter: … }` with no `path` — Jekyll's post header
  interpolates the hash into `src` and emits invalid markup; the port resolves
  the same path the SEO tag uses.

Everything else is compared field by field and matches. `docs/SEO.md` is the
map: every output, its rule, the configuration key and the gate that proves it.

## 6. Compatibility

| | |
|---|---|
| Upstream | `cotes2020/jekyll-theme-chirpy` v7.6.0 (`1520938`) |
| Hugo | 0.150 or newer (tested on 0.168 extended) |
| Node | 22 or newer |
| License | MIT, original copyright preserved |

No configuration changes are required. A site that wants the new knobs sets
`params.logo`, `params.author`, `params.twitter_card`, `params.facebook.*` or
`params.google_site_verification`; the front matter keys are the upstream ones.

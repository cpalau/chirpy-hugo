# Upstream Audit — `jekyll-theme-chirpy` v7.6.0

Deep, file-by-file analysis of the original theme, performed before writing a
single template.

**Method:** downloaded the `v7.6.0` tarball, inventoried all 225 files, and read
every layout, include, JavaScript module and data file. Every claim in
[`FEATURES.md`](FEATURES.md), [`CONFIG.md`](CONFIG.md), [`I18N.md`](I18N.md) and
[`COMPATIBILITY.md`](COMPATIBILITY.md) is traceable to this document.

**Why this exists:** the first draft of the documentation was written from the
public README and file names. The audit found **36 concrete behaviours that the
documentation did not describe or described incorrectly**. Those are listed in
§7 and have been corrected.

### 2.1 `default.html` composition

The shell is not a simple `baseof`: sections are selected by **layout front
matter lists**:

```yaml
panel_includes:   # rendered inside <aside id="panel-wrapper">
tail_includes:    # rendered before the footer
script_includes:  # rendered before </body>
```

`post.html` is the only layout that uses them. In Hugo this becomes explicit
template composition (`define` blocks or a parameterised partial), but the
resulting DOM order must be identical:

```
body
├── aside#sidebar
└── div#main-wrapper
    └── div.container
        ├── header#topbar-wrapper
        ├── div.row
        │   ├── main (content)
        │   └── aside#panel-wrapper
        │       ├── div.access  → update-list + trending-tags
        │       └── toc
        ├── div.row
        │   └── div#tail-wrapper
        │       ├── related-posts
        │       ├── post-nav
        │       └── footer
        └── div#search-result-wrapper
```

Also note: `refactor-content` is applied **only** when the current layout's own
front matter says `layout: default` (home, post). For `page.html` (empty front
matter) it is **not** applied. This is why about/tab pages do not get image
wrappers or code headers.

## 5. `refactor-content.html` — the real rendering layer

287 lines of string manipulation over already-rendered HTML. Hugo must produce
**the same final markup** through render hooks. This is the single most
important finding of the audit.

| # | Transform | Exact behaviour |
|---|---|---|
| R1 | Tables | Wrap every `<table>` in `<div class="table-wrapper">` |
| R2 | Highlight nesting | `<div class="highlight"><pre class="highlight"><code` → `<div class="highlight"><code` and closing equivalent |
| R3 | Task lists | Replace the two kramdown checkbox forms with `<i class="fas fa-check-circle fa-fw checked">` / `<i class="far fa-circle fa-fw">` |
| R4 | Images | Parse attributes; move `preview-img/normal/left/right/light/dark/w-*` classes to a wrapper; `w=`/`h=` → `width=`/`height=`; resolve `media_subpath`; add `loading="lazy"`; with `lqip` → `data-src` + `data-lqip` + `.blur`, without → `.shimmer` |
| R5 | Image wrapper | Home page: `<div class="preview-img …">`; other pages: `<a href="src" class="popup img-link …">` (or reuse an existing `<a>`) |
| R6 | Code header | Prepend `<div class="code-header">` with `<span data-label-text>` (filename if `file="…"`, otherwise the code-language display name) and a copy button carrying the localized "copied" message |
| R7 | Heading anchors | For `h2`–`h5` only: wrap text in `<span class="me-2">…</span>` and append `<a href="#id" class="anchor text-muted"><i class="fas fa-hashtag"></i></a>` |

Consequences for the port:

- `render-table.html` → R1.
- `render-codeblock.html` → R2 + R6 (and the inner Chroma markup must match Rouge, D-02).
- `render-image.html` → R4 + R5 (needs to know the page kind: home vs post).
- `render-heading.html` → R7 (levels 2–5 only; `data-toc-skip` is *not* consulted here).
- Task lists → no render hook exists; use a narrow `replaceRE` on `.Content` or a
  dedicated partial, documented.

## 7. Findings and corrections

Items marked **CORRECTED** changed an existing document.

### 7.1 Rendering and structure

- **G-01 CORRECTED** — The port is not "Liquid → Go templates". The real work is
  reproducing `refactor-content.html` (287 lines of HTML post-processing).
- **G-02 CORRECTED** — Code block headers (label + copy button) are generated by
  `refactor-content`, not by Rouge. `render-codeblock` must emit them.
- **G-03** — The image wrapper differs by page kind (`div.preview-img` on home vs
  `a.popup.img-link` elsewhere). A single `render-image` hook needs context.
- **G-04** — Heading anchors apply to **h2–h5 only**, wrap the text in
  `<span class="me-2">`, and ignore `data-toc-skip`.
- **G-05** — `js-selector.html` contains an operator-precedence quirk:
  `content contains '<h2' or content contains '<h3' and site.toc and page.toc`
  evaluates as `h2 OR (h3 AND toc)`. Reproduce it (parity includes bugs).
- **G-06 CORRECTED** — `language-alias.html` is **not** locale aliasing. It maps
  code-language identifiers (`py` → `Python`) for the code block label. There is
  **no** locale-alias feature upstream.
- **G-07 CORRECTED** — The feed is a **hand-written Atom template**
  (`assets/feed.xml`), not `jekyll-feed`: 5 posts, summary limited to 400 chars.
- **G-08 CORRECTED** — `404.html` and `robots.txt` **do exist** (under `assets/`),
  and the feed is at `/feed.xml`.
- **G-09** — Taxonomy URLs are built with `slugify | url_encode`; the tag index
  uses `sort_natural`, which Hugo cannot reproduce exactly with `sort`
  (case/locale-insensitive). Candidate divergence.
- **G-10** — `home.html` pinned-post pagination is a non-trivial algorithm
  (visible window, pinned_size, normal_start/end). Must be ported literally.
- **G-11 CORRECTED** — Related posts is **custom Chirpy code** (tag 1, category
  0.5, top 3), not Jekyll's `site.related_posts`. **D-08 removed.**
- **G-12** — Read time uses **180 wpm**, not 183 or 200.
- **G-13** — Recently-updated list sorts by `%Y%m%d%H%M%S::index` descending.
- **G-14** — Trending tags caps at 10, ties broken by natural sort.
- **G-15** — Dates are hybrid: server-side `strftime` text plus `data-ts`/`data-df`
  for Day.js to reformat client-side (`ll`, `MMM`). The final visible string is
  produced by JavaScript.
- **G-16** — If `theme_mode` is `light`/`dark`, the toggle disappears, `<html>`
  gets `data-bs-theme`, and the SCSS emits a single theme (`$enable-dual = false`).
- **G-17** — URL joining uses repeated `replace '///' → '/'` and `replace ':/' → '://'`
  after CDN prefixing. Subtle and easy to get wrong.
- **G-18** — Email contact is written as `javascript:void(location.href = 'mailto:' + …)`
  to avoid Firefox opening a blank page (v7.6 fix). Reproduce exactly.
- **G-19** — Comment providers insert nodes **before `<footer>`** and rely on the
  global `Theme` object and `theme-updated` messages.
- **G-20** — `app.min.js` reads `register` and `baseurl` from its **own script URL**
  query string. The URL must be generated identically.
- **G-21** — `swconf.js` includes a build timestamp in `cacheName`
  (`chirpy-<epoch>`), so output is non-deterministic. Tests must freeze time.
- **G-22** — `search.json` carries `swcache: true`, which the service worker uses
  to decide what to precache.
- **G-23 CORRECTED** — `_sass/vendors/` and `assets/js/dist/` are **git-ignored
  upstream** and generated by `npm run build`. A Hugo module consumer cannot run
  npm, so our repository must **commit** these artifacts. They do not need to be
  rebuilt: the **published gem ships all ten** (verified: 136 files identical to
  the tag, zero differences, gem adds exactly those ten), so they are copied
  from the gem and hash-verified in CI (Gate G8, D-10).
- **G-24** — Self-hosting depends on the external repository
  `cotes2020/chirpy-static-assets`, declared as a **git submodule** at
  `assets/lib` in `.gitmodules`. We must mount it as a Hugo module (or a
  submodule) and expose it at `/assets/lib`.
- **G-37** — The home page is a root `index.html` with `layout: home`, not a
  `_layouts` file. In Hugo it is `layouts/home.html`, driven by the home page
  kind; there is no `index.html` to port.
- **G-38** — Per-block `start_line` is **broken upstream**. `{: start_line="10" }`
  makes kramdown emit `start_line="10"` as an attribute on the wrapper *and*
  corrupts the gutter (`refactor-content` loses the `</span>` it string-replaces).
  Only the global `syntax_highlighter_opts.block.start_line` default works. Our
  render hook must not advertise a per-block start line, and no fixture uses it.
- **G-39** — kramdown gives **inline code** the class list
  `language-plaintext highlighter-rouge` (plus any IAL class, in the middle:
  `language-plaintext filepath highlighter-rouge`). `_sass/base/_syntax.scss`
  styles `code.highlighter-rouge` with `background-color: var(--inline-code-bg)`,
  so without the class inline code renders **visually different**. Hugo has no
  inline-code render hook: the port adds the class with one documented
  `replaceRE` over `.Content`, and the `filepath` shortcode emits the same three
  classes.
- **G-40** — Taxonomy URLs are `slugify | url_encode`. Jekyll's `slugify`
  **lowercases but keeps diacritics** (`Ávila` → `%C3%A1vila`), while Hugo's
  `urlize` strips them (`avila`). A Jekyll-compatible slugify partial is
  required, or every accented tag/category URL diverges.
- **G-41** — `hidden: true` only excludes a post from the **home list**. It still
  appears in "Recently Updated" (`update-list`) and in the related-posts
  scoring, because both iterate `site.posts` without the filter. The port must
  reproduce that, not "fix" it.
- **G-25 CORRECTED** — Locale filenames include **U+2011 non-breaking hyphens**
  (`dv‑MV.yml`, `ps‑AF.yml`). The i18n generator must handle them; naive ASCII
  normalisation would silently drop two languages. Also, 9 locales lack the
  `df` block (`bg-BG`, `es-ES`, `fr-FR`, `id-ID`, `my-MM`, `pt-BR`, `tr-TR`,
  `uk-UA`, `vi-VN`), so date formatting falls back to hardcoded defaults.
- **G-26** — The footer prints `theme.version` from the Jekyll gem. Hugo has no
  equivalent; it becomes `params.theme_version` (or derived from module version).
- **G-27 CORRECTED** — The footer credits **Jekyll** and links to the upstream
  repo. A Hugo port must credit Hugo and link to this project. This is a visible
  difference: new divergence **D-09**.
- **G-28** — `site.alt_lang` is read but not defined in the theme `_config.yml`;
  it is an optional site setting for `<html lang>`.
- **G-29** — Pagination uses `paginate_path` (Jekyll default `/page:num/`).
- **G-30 CORRECTED** — Posts support `author` (string) **or** `authors` (array),
  and `image.no_bg`.
- **G-31** — `page.html` localizes tab titles via `page.collection == 'tabs'`.
- **G-32** — TOC requires `site.toc && page.toc` **and** `<h2`/`<h3` in content.
- **G-33** — Search uses `SimpleJekyllSearch` with a `searchResultTemplate` and a
  `templateMiddleware` that wraps categories/tags in icons.
- **G-34** — `post-nav` relies on Jekyll's chronological `previous`/`next`.
  Hugo's `.Prev`/`.Next` semantics are inverted relative to Jekyll; mapping must
  be verified by a fixture with 3+ posts.
- **G-35** — `post-edit` uses `page.path` (source path), which in Hugo is
  `.File.Path`; not available for generated pages.
- **G-36** — `assets/css/jekyll-theme-chirpy.scss` contains Liquid
  (`@use 'abstracts/variables' with ($theme: '{{ site.theme_mode }}')`), so it
  cannot be copied verbatim: our SCSS entry must be generated at build time
  (Hugo `resources.FromString` + `toCSS`).

### 9.1 Answers (F0)

| Q1 | `number_of_words: 'auto'` counts every Han, Katakana, Hiragana and Hangul character as one word **plus** the non-CJK runs. `.WordCount` is whitespace-based: it agrees on Latin, Cyrillic and emoji (9/13 cases) and diverges on every CJK case. | Read time uses `_partials/word-count.html` (`findRE` with `\p{Han}\p{Katakana}\p{Hiragana}\p{Hangul}`), which matches 13/13. | Q4 | Yes. `sort_natural` is `String#casecmp`: ASCII-only case folding, byte comparison, stable.
